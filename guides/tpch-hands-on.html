How it fits together

Goldilox looks at the columns your queries filter on and how many micro-partitions they scan, then recommends the clustering key that would let Snowflake skip the most. This test runs that on a known dataset and workload:

  1. Copy TPC-H SF100~15 min
  2. Grant access~2 min
  3. Lower minimum table size~1 min
  4. Run 22 baseline queries~3 min
  5. Wait for query history15–45 min
  6. Monitor the 8 tables~2 min
  7. Load data~5 min
  8. Generate recommendations10–20 min
  9. Review recommendations~5 min
  10. Apply the keys~5 min
  11. Re-run the 22 queries~3 min
  12. Wait, then compare15–45 min
  13. Clean up~2 min

Allow about 2½ hours end to end, most of it waiting for Snowflake's ACCOUNT_USAGE views to catch up. Do steps 4–8 on the same day: each data load reads only recent query history (the last 24 hours by default).

Before you start

  • Goldilox is installed and opens. Its first-run access screen has been completed, so the app can read query history.
  • Room for 8 monitored tables. Open Recommendations → Monitored Targets. The heading Target Tables (used/limit) shows your limit. The free plan monitors one table. Ask your Goldilox contact to raise the limit to at least 8 for the test.
  • A role that can do the setup. ACCOUNTADMIN is simplest. Any other role must be able to create a warehouse and a database, grant to the app, and read SNOWFLAKE_SAMPLE_DATA and SNOWFLAKE.ACCOUNT_USAGE. To call the app's SQL procedures it also needs the app's GOLDILOX_APP_USER application role.
  • Cost. Expect a few credits of warehouse time, mostly for shuffling the data in step 1 and rebuilding it in step 10, plus Goldilox's own pipeline runs. The copied tables hold about 23 GB until you drop them in step 13.

Why copy, and why random? SNOWFLAKE_SAMPLE_DATA is a read-only share, so it can't be re-sorted later. The sample tables were also loaded in an order that already favours some filters. Copying them in random order removes that, so the "before" run starts from a neutral layout and the "after" run shows what the recommended keys add.

3Lower the minimum table size

In Goldilox, open Settings → Manage App → Advanced settings. Find Minimum table size to analyze, in micro-partitions and write down the current value. If it is above 10, click Update and set it to 10. If it is already 10 or lower, leave it.

Goldilox leaves out queries on tables smaller than this threshold, and sets the value from your own query history. It's often above what the TPC-H queries reach after initial installation.

6Add all eight TPC-H tables to monitoring

Use the SQL tab for this step if you can. The app's table search reads Snowflake's account metadata, which can take up to about 90 minutes to include tables created in step 1.

  1. Open Recommendations and scroll to Monitored Targets.
  2. Expand Add Targets and type in Search table.
  3. Tick Add on all eight TPC-H tables: LINEITEM, ORDERS, PARTSUPP, PART, CUSTOMER, SUPPLIER, NATION and REGION. Then click Add selected to monitoring.
  4. Check that Target Tables lists all eight with ✅ Granted. If one shows 🔴 Need Access, re-run the grants from step 2 and click Refresh Access Status.

If search shows none of the tables, they haven't reached the account metadata yet. Use the SQL tab instead.

9Review the recommendations

Open Recommendations → Clustering Key Recommendations. Each test table shows its recommended key.

SQL

Note each table's recommended columns in the order shown. The order matters: Snowflake sorts by the first column, then by the second within it, so L_SHIPMODE, L_SHIPDATE and L_SHIPDATE, L_SHIPMODE give different layouts.

Example output from one of our runs:

TableRecommended columns, in order
LINEITEML_SHIPMODE, L_SHIPDATE
ORDERSO_ORDERSTATUS, O_ORDERKEY
PARTP_SIZE, P_BRAND
CUSTOMERC_NATIONKEY, C_MKTSEGMENT
SUPPLIERS_NATIONKEY, S_SUPPKEY
PARTSUPP, NATION, REGIONNo key

A table with an empty key means Goldilox found no key that would pay for itself. That's expected for tiny tables like NATION and REGION, and for PARTSUPP, which the TPC-H queries only join on. Leave those tables as they are.

10Apply the recommended keys

Use CREATE OR REPLACE TABLE. It rewrites the table fully sorted by the recommended columns, so the new layout is in place as soon as the statement finishes. ALTER TABLE … CLUSTER BY also works, but it is slower and less thorough.

Rebuild sorted, with the key Recommended

CREATE OR REPLACE TABLE … CLUSTER BY (…) COPY GRANTS AS SELECT … ORDER BY …

  • One-time cost. The table is fully sorted when the statement finishes.
  • COPY GRANTS keeps the app's read access.
  • The table also gets the clustering key, so Automatic Clustering keeps it ordered as data changes.

Add the key to the existing table

ALTER TABLE … CLUSTER BY (…)

  • Snowflake re-sorts the table gradually in the background with Automatic Clustering, billed as serverless credits.
  • Takes hours to settle on tables this size, so the comparison must wait.
  • Background clustering improves the layout step by step and doesn't aim for a full sort, so the result is usually less well ordered than a rebuild.

Troubleshooting

What you seeLikely causeWhat to do
Every table shows No recommendation right after step 8. Goldilox can't read the query profiles because MONITOR on the test warehouse is missing. Run the step 2 grants, then repeat steps 7 and 8. You don't need to re-run the queries.
Only some of the 22 queries count; Goldilox shows few queries per table. The minimum table size from step 3 is still too high. Lower it as in step 3, then repeat steps 7 and 8.
Every table shows No recommendation even though access and MONITOR are in place. The recommendation run started before the data load had finished. Repeat steps 7 and 8, waiting for each run to finish. If it still shows nothing, run the 22 queries again and repeat steps 4, 5, 7 and 8.
Every table shows No recommendation and the database name starts with GOLDILOX. Goldilox skips tables in databases whose names start with GOLDILOX. Use a different database name and start again from step 1.
RUN_PIPELINE returns ALREADY_RUNNING. A run of that pipeline is in progress. Wait for it to finish (step 7 shows how to check), then call it again.
ADD_MONITORED_TARGETS returns NOT_ADDED. The monitored-table limit is reached. Ask your Goldilox contact to raise the limit to at least 8.
A table shows 🔴 Need Access after step 10. The table was rebuilt without COPY GRANTS. Re-run the step 2 grants, then click Refresh Access Status.
The step 12 query shows fewer than 22 queries on a side. Some queries failed, or aren't in query history yet. Wait and run it again. If a query failed, run that query again with the same tag.
